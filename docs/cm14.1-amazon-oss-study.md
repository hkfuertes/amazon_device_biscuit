# CM14.1 Amazon OSS study

## Decision

The first CM14.1 milestone is a reproducible `cm_biscuit-userdebug` build. It
intentionally does not claim bootability or working Biscuit hardware. The
compile-only product inherits the upstream MT8163 common tree and omits the
Biscuit-specific HALs, service, apps, and proprietary blobs until the build
baseline is proven.

## Verified Amazon OSS sources

| Source | CM14.1 status | Initial use |
|---|---|---|
| [`android_device_amazon_mt8163-common`](https://github.com/amazon-oss/android_device_amazon_mt8163-common/tree/cm-14.1) | Has `cm-14.1` (and an explicit `biscuit` target filter) | Synced at `311f54e2878fe74c6aed380e739dd447e2ccea13` as the device common base. |
| [`android_hardware_amazon`](https://github.com/amazon-oss/android_hardware_amazon/tree/cm-14.1) | Has `cm-14.1` | Synced at `fa65a4bee671397b16d3e548463ef80b0144ca81`; provides the MTK-oriented shims, init helpers, lights, power, and graphics helpers referenced by common. |
| [`android_kernel_amazon_mt8163`](https://github.com/amazon-oss/android_kernel_amazon_mt8163/tree/cm-14.1) | Has `cm-14.1` and `3.18/cm-14.1` | Study/reference only. Biscuit uses the verified FireOS 6.5.7.1 Echo Dot kernel as-is instead of this tablet kernel. |
| [`android_vendor_amazon_mt8163-common`](https://github.com/amazon-oss/android_vendor_amazon_mt8163-common) | No `cm-14.1` branch (only `lineage-18.1`) | Not imported. A tracked empty vendor makefile lets the compile baseline resolve the upstream common include. |
| `android_hardware_mediatek_mt66xx` | No `cm-14.1` branch | Not imported. Its later-lineage code is not needed for the initial build. |

The upstream CM14.1 common tree is not a direct Git continuation of the
CM12.1 source used by this repository; GitHub reports no common ancestor.
It must therefore be treated as a new base rather than cherry-picked as a
linear upgrade.

## FireOS 6 kernel baseline

CM14.1 builds the unmodified kernel source from
[Echo Dot 6.5.7.1](https://fireos-audio-src.s3.amazonaws.com/dMUQiRDxI3hFuRDaF0WTumrp71/Echo_Dot_src-6.5.7.1-20251024.tar.bz2)
in its normal kernel graph. The verified archive SHA256 is
`2f6b7eed8c09cecf7633f01909c6a4085bef691c29ed0d106c75e7b48c7b4721`.
Staging materializes Linux 3.18.19 at `kernel/amazon/biscuit`, using Amazon's
`ARCH=arm`, `biscuit_defconfig`, `arm-eabi-4.8`, and `zImage-dtb` contract.
It also stages Amazon's verity key and Trapz generated header so the CM14
build produces both the kernel and `headers_install` output.
`scripts/build-cm14.1-kernel-as-is.sh` remains an independent unmodified
Amazon-build comparison, not an OTA input. OTA staging applies only
`patches/kernel/biscuit-kernel-netfilter-xt-compat-percpu.patch` with
`patch --fuzz=0`; all other kernel patches remain excluded.

## Build-first layout

- `manifest/cm14.1.local.xml` pins the two useful CM14.1 Amazon projects.
- `scripts/sync-cm14.1.sh` initializes LineageOS `cm-14.1`, applies that
  overlay, hydrates the pinned ARM WebView Git LFS APK with SHA validation,
  and writes `manifest/cm14.1.lock.xml` after the first successful sync.
  Future syncs consume the resolved lock.
- `cm14.1/` is a small staging overlay, separate from the CM12 device tree.
  Its product inherits `device/amazon/mt8163-common`, stages the FireOS 6
  kernel source and support files, and retains the known Biscuit boot-image
  layout.
- `scripts/stage-cm14.1-tree.sh` applies the tracked amonet and headless
  property patches to the synced common tree, the source-built software GLES
  and HWUI-config fallbacks to CM14, and the strict-compatible netfilter patch
  to the disposable FireOS kernel tree.
- `scripts/build-cm14.1.sh` launches a detached
  `cm14.1-biscuit-build` container. It deliberately does not apply remaining
  `patches/cm12/` patches.
- `docker/cm14.1-ubuntu20.Dockerfile` uses OpenJDK 8 and enables legacy TLS
  only inside the build image because Jack 4.8 requires it.

## Amonet OTA mapping

The upstream common fstab names stock `system` and `boot` partitions. The
tracked CM14 patch changes only those names to `system_a` and `boot_a_x`, which
are the real amonet ROM targets. It preserves the FireOS 6 physical block path,
recovery, cache, userdata, and GPT. Each generated OTA must still be checked
for those updater-script paths before it is flashed.

## Headless graphics

FireOS 6.5.7.4 is Android 7.1.2 and headless. It ships
`libGLES_android.so`, has no active Mali gralloc property, and disables HWUI
dirty-region rendering. CM14 follows that model without copying its binary:
it packages CM14's source-built `libGLES_android`, falls through to the
source-built default gralloc HAL, and uses narrow Loader/EglManager fallbacks.
It intentionally does not port CM12's global `ro.config.no_gpu` Java guards.

## Deferred on purpose

- Proprietary blobs and their runtime ABI shims.
- Biscuit audio, sensors, LED service, launcher, Bluetooth, Wi-Fi behavior,
  USB gadget behavior, and SELinux policy.
- Any FireOS 6 kernel change beyond the strict-compatible netfilter patch.
- MTK OMX runtime integration: codec XML declarations alone do not provide the
  proprietary OMX implementation or its ABI dependencies.
- Packaging or runtime loading FireOS kernel modules. They compile, but FireOS
  3.18 does not supply `modules_install` support.
- Booting or flashing an artifact.

## First build

```sh
# Required on the host because the CM14.1 WebView prebuilt uses Git LFS.
sudo apt-get install git-lfs

docker build -t cm14.1-ubuntu20:latest \
  -f docker/cm14.1-ubuntu20.Dockerfile docker/
scripts/sync-cm14.1.sh
scripts/build-cm14.1.sh
```

The OTA launcher stages and builds the FireOS 6 kernel source itself. It must
not invoke the CM12 patched kernel pipeline. Monitor the detached OTA with:

```sh
docker logs -f cm14.1-biscuit-build
```
